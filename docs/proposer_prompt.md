# Proposer prompt anatomy

> Last regenerated against `src/services/reeditProposer.js` — keep in sync if you change the prompt builders. This is documentation, not the source of truth; the live prompt is whatever the code emits.

The Proposal tab (and the Auto pipeline's last step) ask Gemini to produce a re-edit EDL by sending a single chat completion with **one `system` message + one `user` message**. The user message is concatenated at runtime from ~10 conditional blocks. The exact text depends on which capabilities the user ticked, which framework / metric they picked, and which optional inputs (Sundogs PDF, generated VO/music, additional footage) are attached.

The model is told to return **JSON only** — every wrapper / explanatory text in this doc is for human reference, not for the model's output.

---

## 1 · System message

Generated by `buildSystemPrompt(capabilities)` (`reeditProposer.js:133`).

```
You are a senior advertising creative director helping to re-edit an
existing commercial <ROLE_TAIL>. You work from a shot log and return
a concrete, ordered edit decision list (EDL) with per-shot rationale.
You return ONLY a JSON object, no commentary, no markdown fences.
```

`<ROLE_TAIL>` is one of:

- **`footageGeneration: true`** → "*using only its already-filmed shots plus, when a structural gap truly requires it, a few AI-generated placeholder shots you explicitly propose*"
- **`footageGeneration: false`** → "*using only its already-filmed shots — you cannot add, generate, or invent new footage*"

That single phrase is the whole "are placeholders allowed?" lever at the system level. The user message reinforces the rule with structured constraints below.

## 2 · User message — block order

Built by `buildUserPrompt({...})` (`reeditProposer.js:930`). Concatenated in this order:

```
# Goal
Re-edit this commercial to improve its <METRIC> score.
<FRAMEWORK_BLOCK>
<SUNDOGS_BLOCK>

# Brand brief
<BRAND_BRIEF>
<EXTRA_INSTRUCTIONS_BLOCK>
<AD_CONCEPT_BLOCK>
<VO_SCRIPT_BLOCK>
<MUSIC_BED_BLOCK>
<CAPABILITIES_BLOCK>
<EDITING_CRAFT_BLOCK>

# Shot log (from the current cut)
<SHOT_LOG_INTRO>

<SHOT_LOG>
<ADDITIONAL_SHOT_LOG>

# Your task
<TASK_LINES>

<BUDGET>

Return ONLY a JSON object in this schema:
<OUTPUT_SCHEMA>

Rules:
<RULES>

PLACEHOLDER QUALITY (...):
<PLACEHOLDER_QUALITY_RULES>
```

Below: what each block contains and which inputs gate it.

---

### 2.1 · `# Goal` line

Single line referencing the chosen `metric`:

```
Re-edit this commercial to improve its Sundogs score.
```

Always present.

### 2.2 · `<FRAMEWORK_BLOCK>`

```
# Framework
<criteria text>
```

Present when the metric has an attached criteria text (e.g. Google's ABCD, Sundogs framework body). The text comes either from `PROPOSAL_METRICS` (factory defaults) or from a user-edited preset. **Omitted entirely** when the metric is a simple one-word label without an attached framework.

### 2.3 · `<SUNDOGS_BLOCK>`

Present only when `sundogsReport` is supplied (user imported a Sundogs PDF and picked the Sundogs metric). Includes:

- Final score % vs benchmark %
- Deltas per dimension (attention, comprehension, persuasion, action)
- Per-dimension "Do well" / "Could explore" arrays from the PDF
- Per-dimension technique values + status (good / evaluate)

The proposer is told to optimise the EDL against the **"Could explore"** items first.

### 2.4 · `# Brand brief`

```
# Brand brief
<text the user typed in ProposalView, or "(not provided — infer from the shot log)">
```

Always present (with the fallback when empty).

### 2.5 · `<EXTRA_INSTRUCTIONS_BLOCK>`

```
# Extra instructions (honor these strictly)
<text>
```

Present only when the user typed something into the "Extra instructions" textarea. Treated as hard rules by the LLM.

### 2.6 · `<AD_CONCEPT_BLOCK>`

```
# Ad concept
- Concept: ...
- Message: ...
- Mood: ...
- Target audience: ...
- Brand role: ...
- Narrative arc: ...
```

Comes from `analysis.overall` (the "overall ad concept" pass that runs after captioning). Present only when at least one of those fields is non-null. Auto runs this step; Simple/Advanced require the user to click "Analyze overall".

### 2.7 · `<VO_SCRIPT_BLOCK>`

Two variants, mutually exclusive:

- **Generated VO** — when `capabilities.generateVoiceover: true` AND a synthesised draft was passed in. The block lists every segment verbatim, locked in order. The proposer is told it cannot pick/reorder these.
- **Original VO (pickable)** — when `capabilities.useOriginalVoiceover: true` AND `voSegments[]` is present. The block lists every original VO segment with its source timecode and lets the LLM pick which ones to include. Tells the model to preserve segment order, never split a line across shots, and to keep total VO duration within the target.

Empty string when neither applies.

### 2.8 · `<MUSIC_BED_BLOCK>`

Renders the user's synthesised music brief (tags, BPM, keyscale, duration) — only when `capabilities.generateMusic: true` AND a draft exists. Empty string otherwise. The original-music stem path doesn't render here (no tempo/genre context yet).

### 2.9 · `<CAPABILITIES_BLOCK>`

Built by `renderCapabilitiesBlock(capabilities)` (`reeditProposer.js:617`). One line per flag. The text changes between an ENABLED and DISABLED rule per flag — the model sees explicit MUST / MUST NOT statements either way. Flags covered:

- `footageGeneration` (+ content filters: `allowProducts`, `allowFaces`, `allowText`, all hard-banned when off; mandatory `referenceFrame` rules when on)
- `footageExtend` (with max seconds from capability settings)
- `footageReframe` (with explicit anchor/zoom format rules and the dead-center auto-rejection)
- `colorCorrection` (with the COLOR directive spec)
- `useOriginalMusic`
- `useOriginalVoiceover`

This is the longest single block in the prompt — typically 60-120 lines of plain text. It's the primary lever the user has over what the LLM is allowed to emit.

### 2.10 · `<EDITING_CRAFT_BLOCK>`

```
# Editing craft (cut-quality rules — apply on every ordering decision)
- Jump cuts — when to use / avoid / cover with B-roll, scale change, motion-motivated cut.
- 180° / screen direction — keep eyeline + Subject bbox side consistent; break only with intent.
- Cut on motion — pair shots whose Motion / camera_movement_quality continue across the boundary.
- Action continuity — when source-ad mismatches would break, insert a cutaway.
- Camera continuity — don't slam-cut between contradicting moves without narrative reason.
- Rhythm with intent — earn density on info beats; earn held shots on emotional beats.
- Hook in first 1–3s — open on the strongest moment, never on a logo / slow establish.
- No churn — don't reorder for the sake of reordering; the proposal is judged by what it improves.
```

Generated by `renderEditingCraftBlock()` (`reeditProposer.js`). **Always present** — universal editing principles that hold regardless of which capabilities / metric / framework are active. Each bullet names the shot-log fields (`Motion`, `Subject`, `Cinematography.shot_size`, etc.) the LLM should consult to make the call, so the rules ground out in concrete data rather than abstract editor-speak.

### 2.11 · `# Shot log` intro + `<SHOT_LOG>`

Fixed intro paragraph explaining the per-shot block format (Visual / Chips / Motion / Cinematography / Audio / Graphics / Pacing). Then one block per scene, generated by `formatSceneBlock(scene)` (`reeditProposer.js:163`), each separated by `---`. Per-shot block shape:

```
## scene-001 · 0.00–2.12s · 2.12s
Optimized: V01 — on-screen graphics have been removed; the Graphics block below describes the ORIGINAL overlays.
End-card: TRUE — this shot is the ad's brand-signature frame. Use it AS-IS in the cut.
Visual: <Gemini's factual description>
Subject: <subject_label> centered at [x, y]
BrandMark: <brand_label> centered at [x, y]    (or "none visible")
Chips: brand=<brand_role> · emotion=<emotion> · framing=<framing> · movement=<movement>
Motion: camera <camera_movement> (intensity: <camera_movement_intensity>); subject <subject_motion> (<direction>)
Cinematography: shot_size=<...> · angle=<...> · rig=<...> · lens=<...> · dof=<...> · focus_dynamics=<...> · composition=<...> · lighting_style=<...> · color_palette=<...> · special_techniques=<...>
Audio: VO "..." · Music: ... · SFX: ... · Ambient: ...
Graphics: text (role) "..." · logo: ... · overlay: ...
Pacing: cut=<hard_cut|match_cut|fade|...> · tempo=<slow|mid|fast|frenetic>
```

Sections with no data are omitted line-by-line, so a silent / clean / non-end-card shot won't have those rows. End-card shots and optimized shots get their flag lines at the top so the LLM scores them with the right mental model.

### 2.12 · `<ADDITIONAL_SHOT_LOG>`

Block of imported footage available via `capabilities.useAdditionalAssets`. Same per-shot format as the main shot log but with `add-*` source ids and a header that tells the LLM "treat as a secondary pool — main ad shots come first."

Omitted when the capability is off or no additional assets exist.

### 2.13 · `# Your task` block

Bulleted list of the tools the LLM is allowed to use **right now**, generated from the capabilities. Always includes:

- "**Always**: reorder shots, cut weak moments, promote high-value shots to prime timecodes."

Plus one bullet per enabled capability (placeholder rows, REFRAME, COLOR, EXTEND, AUDIO music, AUDIO vo) with the exact directive syntax. Bullets for disabled capabilities are silently omitted — the LLM doesn't see them as options at all.

### 2.14 · `<BUDGET>`

The hardest part of the prompt. Computed from `targetDurationSec`, `totalNatural` (sum of source-scene durations of eligible scenes), and which gap-filling tools are on. Has 6 branches:

1. **No gap** — "you can reach target with existing scenes alone"
2. **Gap + EXTEND covers it** — exact per-shot math ("avg +X.X s across N shots")
3. **Gap + EXTEND+placeholders** — split the gap across both tools
4. **Gap + placeholders only** — "~N placeholder rows averaging 2s each"
5. **Gap + EXTEND only** — "use aggressively until sum reaches target"
6. **Gap + nothing enabled** — "final EDL will be shorter than target; that's expected"

Each branch ends with a "SUM the durations before returning; if below the lower bound, add more material" instruction.

When called as a correction pass (the proposer caught the LLM emitting a too-short EDL on the first try), the budget includes a `**CORRECTION REQUIRED**: <reason>` line at the bottom.

### 2.15 · Output schema + Rules + PLACEHOLDER QUALITY

End of the prompt. Contains:

- A minimal JSON example with one `original` row and (when `footageGeneration` is on) one `placeholder` row with its `referenceFrame: { sourceSceneId, framePosition }`.
- 5 short rules: original rows reference existing scenes; placeholders have sourceSceneId null + required referenceFrame; rows contiguous; first row at 0; JSON only.
- A "PLACEHOLDER QUALITY" block with hard bans (no products / brands / text / graphics / end-cards / faces) and director-instruction style rules. Re-emphasised because LLMs tend to drift back to "establishing brand shot" type proposals otherwise.

## 3 · Output schema (what we expect back)

```json
{
  "rationale": "2-4 sentences",
  "edl": [
    {
      "index": 1,
      "kind": "original",
      "sourceSceneId": "scene-001",
      "newTcIn": 0.00,
      "newTcOut": 2.00,
      "note": "Free-text rationale; may carry REFRAME / COLOR / EXTEND / AUDIO directives as prefix."
    },
    {
      "index": 2,
      "kind": "placeholder",
      "sourceSceneId": null,
      "newTcIn": 2.00,
      "newTcOut": 3.50,
      "note": "Director's shot instruction (subject + action + framing + motion + lighting).",
      "referenceFrame": { "sourceSceneId": "scene-003", "framePosition": "end" }
    }
  ]
}
```

Post-processing on the renderer side (also in `reeditProposer.js`):

- Parses `REFRAME zoom=X.X anchor=x,y:` → `row.reframe = {zoom, anchor}`. Drops the directive if dead-center + high zoom (LLM didn't actually localise the subject) or if the anchor would clip a known brand mark out of the post-crop window.
- Parses `COLOR: exposure=±N contrast=±N ...:` → `row.colorAdjustments`.
- Parses `EXTEND +Xs:` → `row.extend = {seconds}`, clamped to capability max.
- Validates `referenceFrame.sourceSceneId` exists in the shot log + `framePosition` ∈ {`start`, `middle`, `end`}; drops malformed entries.

## 4 · How capabilities flip the prompt

| Flag                     | When ON                                                             | When OFF                                                                  |
|--------------------------|---------------------------------------------------------------------|---------------------------------------------------------------------------|
| `footageGeneration`      | System role mentions placeholders. Capabilities block lists max duration + content filters. Output schema example includes placeholder row + `referenceFrame`. Task bullets include "Placeholder rows". | System role says "you cannot add, generate, or invent footage". Capabilities block says "MUST NOT propose any placeholder rows". |
| `footageExtend`          | Task bullet for EXTEND with max seconds. Budget calculations include extend capacity. | Capabilities block says "MUST NOT annotate shots with EXTEND directives". |
| `footageReframe`         | Capabilities block carries the full REFRAME format spec (zoom/anchor/subject lookup rules) + GOOD/BAD examples + the dead-center auto-reject rule. Task bullet enabled. | Capabilities block says "every shot plays at its native framing".         |
| `colorCorrection`        | Capabilities block carries the COLOR key list + ±range guidance. Task bullet enabled. | Capabilities block says "every shot plays with the source grade".         |
| `useOriginalMusic`       | Capabilities block + task bullet allow `AUDIO music:` directive.    | Capabilities block says music stays glued to its source shot.             |
| `useOriginalVoiceover`   | Capabilities block + task bullet allow `AUDIO vo: "..."` directive. VO Script block (pickable) renders. | Capabilities block says VO is bound to its original shot.                 |
| `generateVoiceover`      | When a synthesised draft is attached, VO Script block renders as FIXED (locked order). | No VO script block from synthesis.                                        |
| `generateMusic`          | When a synthesised draft is attached, Music Bed block renders.      | No music bed block.                                                       |
| `useAdditionalAssets`    | Additional shot log block renders.                                  | Block omitted.                                                            |

## 5 · What Auto specifically sends

`reeditLuckyPipeline.js` forces this capability shape regardless of what was persisted on the project:

```js
{
  // From the "Allow:" checkboxes in the Import tab
  footageReframe:    autoCaps.reframe,
  footageGeneration: autoCaps.generate,
  colorCorrection:   autoCaps.color,
  // Hardcoded by Auto (never touches AI audio gen)
  useOriginalVoiceover: true,
  useOriginalMusic:     true,
  useAdditionalAssets:  true,
  generateVoiceover:    false,
  generateMusic:        false,
}
```

Plus `metric: 'Sundogs'` (Auto required the PDF on the Go button, so it always grades against Sundogs). The proposer call is made with everything else (scenes, voSegments, sundogsReport, sourceVideoPath, etc.) pulled from the live project state.

## 6 · Where to read the live prompt

If you want to inspect the exact bytes Gemini receives on a given run, open DevTools → Network in the running Electron app and look for the POST to `https://generativelanguage.googleapis.com/.../models/<model>:generateContent`. The `contents[]` array has the system + user messages verbatim. The renderer doesn't log the prompt anywhere on disk to keep brand briefs / extra instructions out of the project file by default.
